<h1 align='center'>Mirage</h1>
<p align='center'><a href='#'>Discord</a> - <a href='#'>Website</a></p>

<p align='center'><b>Custom roleplay gamemode for the <a href='#'>Mirage</a> server on s&box. Inspired by FiveM RP servers, the project layers all the RP logic, the custom UI, and the server-specific systems on top of Facepunch's official <a href='https://github.com/Facepunch/sandbox'>Sandbox</a> game.</b></p>

## Vision

The project is in early development. The long-term goal:

- **RP identity**: first name, last name, job, ID papers, persistent character sheet
- **Economy**: bank and cash money, transfers, jobs, player-run shops
- **Jobs and factions**: police, paramedic, mechanic, gangs, whitelist
- **Vehicles**: purchase, garages, license plates, mechanical condition
- **Properties**: housing purchase or rent, lockers, shared access
- **RP inventory**: roleplay items (keys, phone, papers, drugs, etc.) on top of the sandbox weapons
- **Phone**: SMS, calls, ads, custom apps
- **RP chat**: OOC and IC, distance-based propagation, radios
- **Admin tools**: staff utilities, logs, sanctions, tickets

Not everything ships at once. We build it brick by brick.

## Technical base

The project is built on top of the source code of the official **Sandbox** game by Facepunch ([Facepunch/sandbox](https://github.com/Facepunch/sandbox)), released under the MIT license. The useful base is kept (players, weapons, physics, spawn menu, undo, save system, NPCs, etc.) and the RP logic is layered on top.

The architecture is documented in [CLAUDE.md](CLAUDE.md): s&box Components and Scene model, host-authoritative networking, `Local.IPlayerEvents` and `Global.IPlayerEvents` event interfaces, `GameObjectSystem<T>` singletons, etc.

## Build

No CLI build. s&box compiles from the editor.

1. Open the **s&box** editor.
2. Add this folder as a project (`mirage.sbproj`).
3. Run the `scenes/sandbox.scene` scene.

`*.csproj`, `*.sln`, `obj/`, `bin/`, `.sbox/` are all generated by the editor and ignored by git. Do not commit them.

## Server launch parameters

The gamemode reads its boot configuration from ConVars, set the standard s&box way: `+convar value` on the dedicated server command line. There is no `server.cfg`-style exec mechanism in s&box, so every tunable goes through the command line at boot (see `Docs/Sbox/reference/dedicated-server.md`).

The Mirage API must be reachable from the gamemode. `mirage.api_url` has to satisfy `Sandbox.Http`'s allowlist (scheme `http` or `https`, no raw IPs, and `localhost` is allowed only on ports 80, 443, 8080, 8443), and `mirage.api_token` must match the backend's `API_BEARER_TOKEN`.

| ConVar | Type | Default | Purpose |
| --- | --- | --- | --- |
| `mirage.api_url` | string | `http://localhost:8080` | Base URL of the Mirage backend API. Must satisfy the s&box HTTP allowlist: scheme `http` or `https`, no raw IPs, and if it points at `localhost` then port 80, 443, 8080, or 8443 only. Use a domain in production. |
| `mirage.api_token` | string | (empty, must be set) | Bearer token shared with the backend (`API_BEARER_TOKEN` in the API's `.env`). Server-private, never replicated to clients. |
| `mirage.api_timeout_ms` | int | `5000` | Per-request HTTP timeout in milliseconds. |
| `mirage.spawn_limbo_height` | float | `4096` | Z-axis offset added to the world origin where freshly connected players are parked while the character selection screen is open. Pick a height that keeps them out of frame. |

Example launch:

```bat
sbox-server.exe ^
    +game lets-pop.mirage facepunch.flatgrass ^
    +hostname "Mirage RP" ^
    +mirage.api_url "https://api.mirage.example" ^
    +mirage.api_token "REPLACE_WITH_BEARER_TOKEN" ^
    +mirage.api_timeout_ms 5000
```

### Editor mode (no command line)

When playtesting from the s&box editor, there is no command line to pass `+convar` switches on. The gamemode falls back to a JSON file in the per-game data directory: on first host boot it writes a stub at `FileSystem.Data/mirage_config.json` (typically `data/lets-pop/mirage/mirage_config.json` under the s&box data root), then applies it on every subsequent boot. Fill in `ApiToken` (and any other field you want to override) and re-run.

```json
{
    "ApiUrl": "http://localhost:8080",
    "ApiToken": "REPLACE_WITH_BEARER_TOKEN",
    "ApiTimeoutMs": 5000,
    "SpawnLimboHeight": 4096
}
```

The command line still wins. Each field is only pulled from the file if the matching ConVar is still at its default value, so `+mirage.api_token foo` on a dedicated server overrides whatever sits on disk.
